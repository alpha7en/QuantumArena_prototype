# Классификация задач sparq arena

У банка две независимые системы классификации и одно дерево, которое их связывает.

| Система | Отвечает на вопрос | Где записана в карточке | Для чего нужна |
|---|---|---|---|
| **A. Типизация** | Что на входе, что сдаёт участник, что разрешено, как проверяется | `facets`, `qubits`, `limits`, `scoring` | Поля хранения, отображение задачи, выбор способа проверки |
| **B. Способ составления** | Из чего и как задача сделана | `method`, `level` | Сложность, поиск новых задач, сбалансированность банка |
| **Дерево** | Где задача стоит среди остальных | `tree` | Навигация, учебные треки, поиск пустых мест |

Источники, на которых построена классификация: пять осей и шесть архетипов из материалов команды
([`docs/TASKS.md`](../docs/TASKS.md), [`presentation/QuantumArena_CLASSIFICATION.pdf`](../presentation/QuantumArena_CLASSIFICATION.pdf)),
шаблон разбора чужих задач ([`archive/reference_tasks_v1/TASK_TEMPLATE.md`](../archive/reference_tasks_v1/TASK_TEMPLATE.md)),
расширенные архетипы каталога разнородных задач ([`presentation/QuantumArena_Diverse_Tasks_Catalog.pdf`](../presentation/QuantumArena_Diverse_Tasks_Catalog.pdf))
и отношения эквивалентности из работы о проверке генераторов схем ([`ladder_ec`](https://github.com/alpha7en/ladder_ec/tree/v1.0.0)).

## A. Типизация: фасеты задачи

Каждый фасет — отдельное поле карточки с закрытым списком значений. Задача — точка в произведении фасетов.
Список значений проверяет `bank/tools/verify.py`; расширять его можно только вместе со схемой
[`schema/task.schema.json`](schema/task.schema.json).

### A1. Вход — `facets.input`

| Значение | Что получает схема | Что это значит для проверки | Примеры |
|---|---|---|---|
| `zero` | $\lvert0\dots0\rangle$ | сравнивается одно состояние | SA-001, SA-010 |
| `any` | произвольное неизвестное состояние | сравнивается преобразование целиком | SA-011, SA-016 |
| `reg_anc` | рабочий регистр в любом состоянии и чистые вспомогательные кубиты | преобразование на подпространстве, анциллы обязаны вернуться в $\lvert0\rangle$ | SA-020, SA-028 |
| `promise` | состояние из обещанного набора | проверка только на этих состояниях | SA-046, SA-051 |
| `oracle` | чёрный ящик: гейт, устройство которого неизвестно | прогон на наборе скрытых ящиков, лимит вызовов | SA-030, SA-036 |
| `resource` | заранее разделённая запутанность, локальные операции участников | платформа сама собирает полную схему протокола | SA-053, SA-054 |

### A2. Что сдаёт участник — `facets.answer`

| Значение | Контракт | Где решается | Примеры |
|---|---|---|---|
| `fixed` | `solve() -> QuantumCircuit`, схема без параметров | редактор схем или код | SA-001, SA-014 |
| `generator` | `solve(n, ...) -> QuantumCircuit`, схема зависит от параметров | только код | SA-005, SA-026 |
| `dynamic` | схема с промежуточными измерениями и условными гейтами | редактор с классическими проводами или код | SA-047, SA-049 |
| `hybrid` | программа: строит схемы, вызывает запуск, возвращает классический результат | только код | SA-038, SA-061 |
| `value` | число или строка без схемы | поле ответа | SR-083, SR-151 |

Поле `gui: true` отмечает задачи, которые целиком собираются в визуальном редакторе. Оно вычислимо из `answer`
и параметров, но хранится явно: по нему строится фильтр «решается без кода».

### A3. Параметры — `facets.params`

Список параметров функции `solve`. У каждого — `name`, `kind` и диапазон или пояснение.

| `kind` | Смысл | Пример |
|---|---|---|
| `size` | размер задачи: число кубитов или разрядов | `n` в SA-003 |
| `data` | классические данные: число, строка битов, граф, список | `L` в SA-010, `edges` в SA-060 |
| `angle` | вещественный параметр | `theta` в SA-058 |
| `repeat` | число повторений одного и того же блока | `r` в SA-059, `k` в SA-045 |
| `circuit` | гейт-аргумент, в том числе чёрный ящик | `oracle` в SA-030 |
| `callback` | функция платформы, которую вызывает решение | `run` в SA-038 |

Виды `repeat`, `size` и `data` соответствуют типам параметров P1, P2 и P5 из `ladder_ec`
(`data/own_generators/tasks_classic.py`, `tasks_qcoder.py`). Соответствие остальным типам статьи нужно
сверить с её текстом: из окружения, где собирался банк, arXiv был недоступен.

### A4. Набор гейтов — `facets.gates`

| `mode` | Смысл | Пример |
|---|---|---|
| `free` | любой гейт интерфейса | — |
| `basis` | закрытый список разрешённых гейтов | $\{H, CX\}$ в SA-003 |
| `native` | набор конкретного процессора | $\{CZ, R_z, \sqrt{X}\}$ в SA-040 |

`set` — имена гейтов в нотации Qiskit (`h`, `cx`, `mcx`, `rz`…). Действует принцип позитивного контракта: в
условии перечислено только разрешённое. Запреты отдельным списком не хранятся, кроме поля `forbid` для
инструкций, которые иначе были бы разрешены режимом измерений (например, `reset` в SA-047).

### A5. Связность — `facets.coupling`

`all` · `line` · `ring` · `star` · `custom` (со списком рёбер `facets.edges`). Двухкубитный гейт допустим
только на ребре графа, гейты на трёх и более кубитах при ограниченной связности запрещены.

### A6. Вспомогательные кубиты — `facets.ancilla`

| `kind` | Смысл |
|---|---|
| `none` | вспомогательных кубитов нет |
| `clean` | начинают в $\lvert0\rangle$ и обязаны вернуться в $\lvert0\rangle$ |
| `dirty` | заимствованные: произвольное состояние, обязаны остаться прежними (SA-029) |

`max` — бюджет анцилл; полный размер схемы ограничен полем `qubits` (`data` плюс `ancilla_max`). Участник вправе
использовать меньше анцилл, чем эталон, — проверка от этого не зависит.

### A7. Измерения — `facets.measure`

`none` — измерений нет; `final` — только в конце схемы; `mid` — промежуточные измерения и гейты под
классическим условием.

### A8. Способ проверки — `facets.check`

Первые шесть значений — отношения эквивалентности из `ladder_ec` (таблица Relations в его README). Для них
спецификация задачи — изометрия $W$: вход на рабочих кубитах, остальные в $\lvert0\rangle$.

| Значение | Что сравнивается | Фаза | Ключ в данных `ladder_ec` |
|---|---|---|---|
| `eq` | оператор $U$ | учитывается | E1 |
| `eq_phase` | оператор $U$ | с точностью до глобальной | E2 |
| `eq0` | состояние $U\lvert0\dots0\rangle$ | учитывается | E5strict |
| `eq0_phase` | состояние $U\lvert0\dots0\rangle$ | с точностью до глобальной | E5phase |
| `eq_anc` | оператор на рабочих кубитах, анциллы возвращены в $\lvert0\rangle$ | учитывается | E3 |
| `eq_anc_phase` | то же | с точностью до глобальной | E3phase |

Отношения с анциллами (`eq_anc`, `eq_anc_phase`) ставятся, когда у задачи есть вспомогательные кубиты или вход
ограничен подпространством (часть кубитов заведомо в $\lvert0\rangle$, как в SA-019). Если анцилл нет и вход —
весь регистр, пишется `eq` или `eq_phase`, даже для оракулов: так требует определение отношений в `ladder_ec`,
который на отношение с анциллами при эталоне без анцилл отвечает «reference does not return its ancillas».
Фасет `input: reg_anc` при этом сохраняется — он описывает роли кубитов (регистр и кубит ответа), а не способ
сравнения.

Остальные значения — проверки, которые не сводятся к сравнению двух схем.

| Значение | Что проверяется | Примеры |
|---|---|---|
| `dist` | распределение результатов измерения совпадает с ожидаемым | SA-034, SA-048 |
| `prob` | вероятность нужного исхода не ниже порога на каждом скрытом ящике | SA-030, SA-054 |
| `channel` | условие выполнено в каждой ветви промежуточных измерений | SA-049, SA-057 |
| `classical` | классический ответ программы: точное значение или допуск | SA-038, SA-061 |
| `fidelity` | точность не ниже порога (приближённые задачи, шум) | SR-120, SR-148 |
| `score` | корректность по отношению из `scoring.relation`, затем баллы по метрике | SA-044 |

### A9. Бюджеты — `limits`, `budget`, `scoring`

`limits` — пределы на метрики одной схемы: `gates`, `depth`, `two_qubit`, `cx`, `t`, `oracle_calls`,
`measurements`. Значение — число или выражение от параметров (`'ceil(n/2)+1'`). `budget` — пределы на всё
решение для ответа `hybrid`: число запусков `runs`, измерений `shots`, допуск `tolerance`. `scoring` — формула
баллов для задач с открытым оптимумом.

### Архетип как сочетание фасетов

Ствол дерева задаёт типичные значения двух главных фасетов. Задача может отклоняться от них — тогда её
принадлежность определяет главная идея.

| Ствол | Название | Типичный вход | Типичная проверка | Было в материалах |
|---|---|---|---|---|
| T1 | Подготовка состояния | `zero` | `eq0_phase` | T1 |
| T2 | Синтез преобразования | `any` | `eq_phase` | T2 |
| T3 | Оракулы и обратимая арифметика | `reg_anc` | `eq_anc_phase` | T3 |
| T4 | Алгоритмы с чёрным ящиком | `oracle` | `prob` | T4 |
| T5 | Ограничения железа | `any` | `eq_phase` и `score` | T5 |
| T6 | Измерения, динамические схемы и коррекция ошибок | `promise` | `channel` | T6; T9 каталога |
| T7 | Протоколы, игры и криптография | `resource` | `prob` | T7 и T10 каталога |
| T8 | Моделирование и вариационные схемы | `zero` | `eq_phase` и `classical` | T8 каталога |

## B. Способ составления: из чего сделана задача

Поле `method.kind` говорит, каким приёмом задача получена. `method.elements` перечисляет элементы, которые в
ней соединены, `method.key_idea` — одна фраза о том, что нужно заметить.

| `kind` | Как получается задача | Пример из ядра | Обычный уровень |
|---|---|---|:-:|
| `fact` | Один факт или тождество | SA-011: $HXH=Z$ | 1 |
| `generalize` | Известная схема обобщается по параметру | SA-003: GHZ для любого $n$ | 1–2 |
| `combo` | Два-три приёма соединяются в одну схему | SA-028: перенос, развычисление, бюджет анцилл | 2–3 |
| `constraint` | Знакомая задача под ограничением, которое ломает наивное решение | SA-005: GHZ на цепочке при бюджете глубины | 2–3 |
| `reverse` | Реверс-инжиниринг: дана готовая схема, чёрный ящик или «странное» условие, нужно понять устройство | SA-042: сжать схему; SA-035: узнать гейт | 1–3 |
| `transfer` | Перенос сюжета: механика из олимпиадной задачи, протокола или прикладной области | SA-054: игра CHSH; SA-038: алгоритм Саймона | 2–3 |
| `open` | Открытый оптимум: верных решений много, баллы за стоимость | SA-044: Тоффоли на цепочке | 3 |

### Уровни

Три уровня. Уровень определяют число соединённых элементов и способ составления; он хранится отдельным полем и
может меняться после калибровки на участниках — идентификатор задачи от него не зависит.

| Уровень | Состав | Способы | Пример |
|---|---|---|---|
| **1 — вход** | один элемент, фиксированный вход или один простой параметр | `fact`, простой `generalize`, простой `reverse` | SA-001, SA-020 |
| **2 — практика** | элемент и одно ограничение либо два элемента | `combo`, `constraint`, `generalize`, `transfer` | SA-005, SA-022 |
| **3 — контест** | три и более элементов, либо два ограничения сразу, либо программа с бюджетом запусков, либо оценка по стоимости | `combo`, `constraint`, `transfer`, `open` | SA-010, SA-061 |

Четырёхуровневая матрица из материалов к акселератору переводится так: 1 → 1, 2 → 2, 3 и 4 → 3. Задачи бывшего
уровня 4 («экзамен, отбор») отличаются полем `scoring` или фасетом `check: score`, а не отдельным уровнем.

Правила гибридизации из [`docs/TASKS.md`](../docs/TASKS.md) действуют без изменений: у гибрида должен быть
способ проверки, эталон готов до публикации, перебор не решает задачу, один новый элемент на уровень.

## Дерево

[`tree.yaml`](tree.yaml) — единственный источник правды о стволах и ветвях. Ствол — архетип, ветвь — ключевая
концепция, плод — задача. Задача принадлежит одной ветви (`tree.branch`) и может ссылаться на смежные
(`tree.hybrid`): так записываются гибриды.

- [`tree.html`](tree.html) — интерактивная схема дерева с фильтрами по уровню, банку и типу ответа;
- [`INDEX.md`](INDEX.md) — таблица ядра;
- [`RESERVE.md`](RESERVE.md) — таблица резерва.

Каждая из 38 ветвей содержит хотя бы одну задачу ядра или идею резерва; `build_docs.py` падает, если появилась
пустая ветвь. Новая концепция добавляется в `tree.yaml` вместе с первой задачей.

## Карточка задачи: поля

Карточка — файл `task.yaml` в пакете задачи. Таблица ниже — рабочий список полей для хранения в базе данных и
вывода на экран.

| Поле | Тип | Обяз. | Где используется |
|---|---|:-:|---|
| `id` | строка `SA-NNN` | да | постоянный идентификатор; не зависит от уровня и ветви |
| `slug` | строка | да | адрес страницы задачи |
| `title` | строка | да | список и страница задачи |
| `aliases` | список строк | нет | прежние идентификаторы (SA-101, SA-205) |
| `status` | `idea` · `draft` · `reference` · `reviewed` · `published` | да | видимость; см. жизненный цикл |
| `level` | 1–3 | да | фильтр, рейтинг сложности |
| `tree.trunk`, `tree.branch`, `tree.hybrid` | идентификаторы из `tree.yaml` | да | навигация, треки |
| `facets.*` | см. раздел A | да | фильтры, выбор редактора, выбор проверки |
| `qubits.data`, `qubits.ancilla_max` | число или выражение | да | лимит размера схемы |
| `limits`, `budget`, `scoring`, `forbid` | см. A9 | нет | строка ограничений, каскад проверок |
| `signature` | строка | да | шаблон кода в редакторе |
| `starter` | текст | нет | стартовый код или схема |
| `method.kind`, `method.elements`, `method.key_idea` | см. раздел B | да | внутренний поиск, разбор |
| `source.kind`, `source.ref`, `source.note` | `own` · `adapted` · `real` | да | атрибуция, лицензионный контроль |
| `gui` | логическое | да | фильтр «без кода» |
| `io.input`, `io.output` | строки с формулами | да | строки «вход» и «цель» в карточке списка и на странице |
| `statement` | Markdown с формулами LaTeX | да | условие |
| `hints` | список строк | нет | подсказки по одной |
| `editorial` | Markdown | да | разбор после решения |
| `pitfalls` | список строк | да | типичные ошибки; каждой соответствует неверное решение в `check.py` |

Формулы во всех текстовых полях записываются в LaTeX между знаками `$`; символов Юникода вместо команд LaTeX
в формулах нет.

### Пакет задачи

```
bank/core/SA-005-ghz-line-depth/
  task.yaml       карточка: метаданные, условие, подсказки, разбор
  reference.py    эталонное решение: функция solve
  check.py        проверка: spec и GRID либо verify; WRONG — «почти верные» решения
```

`check.py` бывает двух видов. Для шести отношений эквивалентности он задаёт `spec(**params)` — изометрию $W$,
записанную независимо от эталона, — и `GRID`, список наборов параметров. Для остальных проверок он задаёт
`verify(solve, task, kit)`. Словарь `WRONG` содержит решения, которые обязаны быть отклонены.

### Жизненный цикл

| Статус | Что есть | Шаг методики |
|---|---|---|
| `idea` | запись в `reserve.yaml` | идея |
| `draft` | пакет заведён, проверка ещё не проходит | карточка |
| `reference` | эталон проходит, неверные решения отклоняются | эталон и тесты |
| `reviewed` | второй эксперт решил задачу вслепую | ревью |
| `published` | задача прошла бету и открыта участникам | бета |

Все 61 задача ядра сейчас в статусе `reference`: ревью вторым экспертом и бета не проводились.

## Источники и права

Поле `source.kind`:

- `own` — задача придумана командой;
- `adapted` — взята известная конструкция или задача, условие существенно изменено (другие ограничения,
  другой формат ответа);
- `real` — механика реальной задачи соревнования сохранена, условие написано заново.

В ядре: `real` — 28, `adapted` — 23, `own` — 10. Во всех случаях действует правило «механика, а не текст»:
формулировки чужих задач в банк не копируются, источник указан в `source.ref`.
