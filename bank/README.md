# Банк задач sparq arena

Здесь лежат задачи платформы в том виде, в котором их должен хранить и показывать сервер: карточка с
классификацией, условие, эталонное решение и проверка. Это рабочий формат для команды и для разработчиков
многостраничного сайта; задачи демо в `assets/js/data/tasks/` остаются как есть.

| Что | Где | Сколько |
|---|---|--:|
| Ядро: эталонные задачи с условием, решением и проверкой | [`core/`](core), таблица — [`INDEX.md`](INDEX.md) | 87 |
| Резерв: идеи на будущее | [`reserve/reserve.yaml`](reserve/reserve.yaml), таблица — [`RESERVE.md`](RESERVE.md) | 147 |
| Дерево: стволы-архетипы и ветви-концепции | [`tree.yaml`](tree.yaml), схема — [`tree.html`](tree.html) | 8 и 38 |
| Две системы классификации и поля карточки | [`CLASSIFICATION.md`](CLASSIFICATION.md) | — |
| Старые задачи (43 из демо, 56 разобранных) в новой классификации | [`LEGACY.md`](LEGACY.md) | 99 |
| Схема карточки для валидации и импорта в базу | [`schema/task.schema.json`](schema/task.schema.json) | — |

Ядро по уровням: 32 задачи первого уровня, 36 второго, 19 третьего. По типу ответа: 43 фиксированные схемы,
33 генератора, 8 динамических схем, 3 программы. Ответ схемой в визуальном редакторе (`gui: true`) поддерживают
50 задач: 25 из 32 на первом уровне, 17 из 36 на втором, 8 из 19 на третьем; критерий — в
[`CLASSIFICATION.md`](CLASSIFICATION.md#ответ-схемой-поле-gui).

## Как устроена задача

```
core/SA-005-ghz-line-depth/
  task.yaml       карточка: классификация, ограничения, условие, подсказки, разбор, типичные ошибки
  reference.py    эталонное решение — функция solve
  check.py        проверка: независимая спецификация и наборы параметров; неверные решения, которые обязаны не пройти
```

Формулы в условиях записаны в LaTeX. Имена гейтов и сигнатуры — как в Qiskit 2.x: эталоны исполняются настоящим
Qiskit, а не интерпретатором демо.

## Проверка

```bash
pip install qiskit numpy pyyaml jsonschema
python3 bank/tools/verify.py              # все задачи ядра
python3 bank/tools/verify.py SA-026       # одна задача
python3 bank/tools/build_docs.py          # пересобрать INDEX.md, RESERVE.md, tree.html
```

`verify.py` для каждой задачи проверяет карточку по схеме, прогоняет эталон по всем наборам параметров и
убеждается, что каждое «почти верное» решение из `check.py` отклонено. Сейчас проходят все 87 задач, отклонено
154 неверных решения.

Набор `tools/sakit.py` — заглушка тестирующей системы: численная симуляция на малых размерах (до 16 кубитов для
состояний, до 10 для операторов). Он повторяет интерфейс будущей системы — шесть отношений эквивалентности из
[`ladder_ec`](https://github.com/alpha7en/ladder_ec/tree/v1.0.0) и особые режимы (распределение, чёрный ящик,
динамические схемы, программа с бюджетом запусков) — но не заменяет её: тесты здесь открыты, а доказательства
эквивалентности для всех $n$ нет.

## Что ещё не сделано

- Ни одну задачу не решал вслепую второй эксперт; статус всех карточек — `reference`, не `reviewed`.
- Время на решение и доля решивших не измерялись: уровни выставлены по матрице, а не по статистике.
- Тексты условий не проходили редактуру и юридическую проверку источников (см. конец `CLASSIFICATION.md`).
- Задач с ответом-числом (`value`) и с шумом в условии в ядре нет, только идеи в резерве.
- Статья о `ladder_ec` (arXiv:2611.12049) при сборке банка была недоступна из окружения; соответствие типов
  параметров и отношений взято из репозитория `ladder_ec`, а не из текста статьи.

## Как добавить задачу

1. Выберите ветвь в `tree.yaml` (или добавьте новую вместе с задачей) и запись в резерве, если она есть.
2. Скопируйте пакет похожей задачи в `core/SA-NNN-slug/`, следующий свободный номер.
3. Заполните карточку: фасеты, ограничения в виде позитивного контракта, способ составления.
4. Напишите `spec` независимо от эталона — формулой, таблицей истинности, перестановкой.
5. Напишите эталон и хотя бы одно неверное решение на каждую строку `pitfalls`.
6. `python3 bank/tools/verify.py SA-NNN`, затем `python3 bank/tools/build_docs.py`.
7. Уберите запись из `reserve.yaml`, если задача выросла из неё.
