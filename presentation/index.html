ТАКСОНОМИЯ ВХОДОВ • ДЕРЕВО 1: НАЧАЛЬНЫЕ СОСТОЯНИЯ

Таксономия начальных состояний кубитов (Входы)

|0...0⟩

1. Фиксированный вакуум

Начальное состояние строго известно и детерминировано.

👉 Задачи: Синтез состояний Белла, GHZ, W-state, Dicke states, кластерных состояний.
|ψ_in⟩

2. Произвольный вектор

Входное состояние неизвестно. Цепь должна реализовать точный оператор U для любого |ψ⟩.

👉 Задачи: QFT, SWAP кубитов, фазовые отражения, квантовая телепортация.
|ψ(θ)⟩

3. Параметрический класс

Вход принадлежит семейству состояний, заданных набором вещественных углов θ.

👉 Задачи: Вариационные анзацы (VQE), калибровка углов, дифференциальные фазы.
|x⟩|0⟩ₐ

4. Регистр + Анциллы

Входное значение x подается с набором чистых вспомогательных анцилл в |0⟩.

👉 Задачи: Квантовые оракулы, обратимая арифметика с Uncomputation.
🛡️ Проверка автосудьи: Для |0⟩ — Statevector Fidelity • Для |ψ_in⟩ — Унитарная матричная норма • Для анцилл — Purity Test
ТАКСОНОМИЯ ВЫХОДОВ • ДЕРЕВО 2: КОНТРАКТЫ РЕШЕНИЯ

Таксономия форматов решения и контрактов (Выходы)

ТИП A: СТАТИЧЕСКИЙ N = const

Фиксированная схема

Схема статична (например, Bell state, Full Adder). Задача на 100% собирается в визуальном GUI-симуляторе простым перетаскиванием гейтов.

GUI Composer: Разрешен
Код в SDK: Автогенерация
ТИП B: ПАРАМЕТРИЧЕСКИЙ solve(n, s, ...)

Программный генератор

Схема строится кодом в зависимости от входных данных (число кубитов n, скрытая маска s). В песочнице дается интерактивный селектор тестового среза.

Контракт: def solve(n) -> QC
Тестирование: 50+ случайных наборов
ТИП C: ДИНАМИЧЕСКИЙ Shots / Feedback

Классическая обратная связь

Схема содержит измерения в середине цепи (mid-circuit measurements), условные вентили c_if или статистическое сэмплирование исходов.

Рантайм: AerSimulator (Shots)
Тестирование: χ²-статистика распределений
Двусторонняя синхронизация платформы: Графическая схема ⟷ Python Qiskit код.
АППАРАТНЫЕ БАЗИСЫ • ДЕРЕВО 3: НАБОРЫ ГЕЙТОВ

Таксономия наборов гейтов и физических базисов

1. Universal
{H, S, T, X, Y, Z, CX, CZ, Rx, Ry, Rz}

Стандартный универсальный базис квантовой информации (Clifford+T).

2. Reversible
{X, CX, CCX / Toffoli}

Классическая обратимая логика (сумматоры, компараторы, булевы функции).

3. Clifford
{H, S, CX, CZ}

Стабилизаторные схемы. Моделируются классически за O(poly(n)) по Готтесману-Книллу.

4. IBM Native
{CZ, Rz(θ), √X, X}

Сверхпроводниковые трансмоны. Гейт Адамара H синтезируется через Rz·√X·Rz.

5. IonQ Native
{MS(θ), Rx(θ), Ry(θ)}

Ионные ловушки: 2-кубитные перепутывающие вентили Мельмера-Зеренсена.

💡 Инженерная ценность: Трансляция под физический базис превращает олимпиадную задачу в реальный индустриальный R&D!
ТОПОЛОГИЯ КУБИТОВ • ДЕРЕВО 4: COUPLING MAP

Топология связности кубитов (Coupling Map)

All-to-All (Kₙ)

Полная связность

Прямой 2-кубитный гейт разрешен между любой парой (qᵢ, qⱼ).

Идеальный симулятор / Ионные ловушки
Linear Chain

Линейная цепочка

Связь только между соседями q₀—q₁—q₂—q₃ (|i-j| = 1).

Требуется SWAP-маршрутизация
Star / Tree

Звезда / Дерево

Центральный кубит-контроллер соединен с периферийными узлами.

Оптимально для оракулов XOR / BV
Heavy-Hex / Grid

Реальный чип IBM

Шестиугольная решетка связей физического процессора (Eagle/Heron).

Zero-overhead транспайлинг QEC
🛡️ Валидатор автосудьи (CouplingMapValidator): Статическая проверка списка ребер E. При неразрешенном гейте — вердикт `TopologyViolationError`.
ДИНАМИЧЕСКИЕ ЦЕПИ • ДЕРЕВО 5: ОБРАТНАЯ СВЯЗЬ

Динамические цепи и классическая обратная связь

1. Mid-Circuit Measurement

Измерение квантового состояния прямо в ходе вычислений с записью в классический регистр c[i].

Применение: Квантовая телепортация, измерение синдромов QEC.

2. Feed-Forward (c_if)

Условное выполнение унитарного гейта qc.x(q).c_if(c, 1) на основе классического бита.

Применение: Коррекция ошибок, Iterative Phase Estimation (IPE).

3. Active Reset

Активный аппаратный сброс кубита qc.reset(q) обратно в состояние |0⟩ для повторного использования.

Применение: Экономия физических кубитов в глубоких схемах.
⚠️ «Серая зона»: Statevector падает на измерениях! Автосудья использует AerSimulator со сбором статистики исходов.
