# 7. Песочница и симулятор: базовый уровень и заглушки

[← к оглавлению](README.md)

## 7.1. Статус

Симулятор и редактор схем демо работают и переносятся на платформу как есть. Развитие симулятора — отдельная
работа; в этом ТЗ фиксируются границы модулей и интерфейсы, чтобы движок можно было заменить, не переписывая
редактор и страницы.

Правило, которое нельзя нарушать: **симулятор в браузере нужен для отклика и наглядности, вердикт выносит
только сервер** (раздел 6).

## 7.3. Границы модулей

При переносе код демо раскладывается на три пакета без зависимостей от страниц и от фреймворка интерфейса.

| Пакет | Содержимое | От чего зависит |
|---|---|---|
| `quantum-core` | модель схемы, гейты, симуляторы, форматирование, подсчёт ресурсов (гейты, глубина, двухкубитные) | ни от чего |
| `qiskit-lite` | интерпретатор и перевод «код ↔ схема» | `quantum-core` |
| `board` | доска на SVG, палитра, диски | `quantum-core`; стили дизайн-системы |

Пакеты переводятся на TypeScript с сохранением поведения; существующие тесты
([`tests/core.test.mjs`](../../tests/core.test.mjs), [`tests/judge.test.mjs`](../../tests/judge.test.mjs))
переносятся вместе с ними и остаются зелёными.

### Интерфейс движка

Редактор и песочница обращаются к симулятору только через интерфейс. Сегодня за ним — движок демо; завтра —
любой другой.

```ts
interface SimulationEngine {
  readonly id: string;                       // "js-statevector-v1"
  readonly limits: { maxQubits: number; maxOps: number; supportsNoise: boolean; supportsDynamic: boolean };
  run(circuit: Circuit, options?: { initial?: Complex[]; upToColumn?: number }): Promise<SimulationResult>;
  sample(circuit: Circuit, shots: number, seed?: number): Promise<Record<string, number>>;
  cancel(): void;
}

interface SimulationResult {
  state?: Complex[];                         // вектор состояния, если схема без измерений
  probabilities: number[];                   // по базисным состояниям
  perQubit: { p1: number; phase: number; entangled: boolean }[];   // данные для дисков на проводах
  resources: { qubits: number; gates: number; depth: number; twoQubit: number };
}
```

Требования к использованию интерфейса:

- вызовы асинхронны, расчёт идёт в фоновом потоке браузера, интерфейс не замирает;
- новый расчёт отменяет предыдущий (участник перетаскивает гейт — старый результат не нужен);
- редактор спрашивает `limits` и сам сообщает: «схема больше 12 кубитов — предпросмотр состояния отключён,
  отправка возможна».

## 7.4. Базовый уровень: что обязано работать при запуске

1. Всё из таблицы 7.2 — без потери возможностей.
2. Отклик на изменение схемы: до 50 мс для схем до 8 кубитов, до 300 мс для 12 кубитов; расчёт не блокирует
   интерфейс.
3. Редактор задачи для ответов `fixed` — доска и код синхронны; для `generator` и `hybrid` — код и
   предпросмотр схемы при выбранном параметре; ресурсы и лимиты считаются при каждом изменении.
4. Песочница: до 8 кубитов на доске; примеры; режим «по шагам»; измерения; разложение гейтов; ссылка.
5. Короткие ссылки песочницы на сервере (`/sandbox/{code}`); длинные ссылки демо со схемой в адресе
   продолжают открываться.
6. Сообщения интерпретатора — на русском, с номером строки и подсказкой, как в демо.
7. Черновики: схема и код сохраняются автоматически (раздел 4).

## 7.5. Заглушки

Каждая заглушка — место в коде и в интерфейсе, где сегодня стоит простое решение или честное «пока
недоступно», а контракт уже окончательный.

| Заглушка | Что стоит сейчас | Контракт на будущее | Как развивать |
|---|---|---|---|
| Движок симуляции | движок демо на JavaScript | `SimulationEngine` (7.3) | движок на WebAssembly для 20 и более кубитов; выбор движка по размеру схемы |
| Настоящий Qiskit в редакторе | интерпретатор Qiskit-lite; надпись «код исполняется упрощённым интерпретатором, вердикт — на сервере» | `POST /api/v1/sandbox/run`: код → схема в переносимом виде и журнал; сейчас адрес отвечает «не реализовано» | серверный запуск в том же исполнителе, что у судьи (раздел 6.5), с жёстким ограничением частоты; либо Pyodide в браузере |
| Динамические схемы на доске | доска показывает такую схему только для чтения; собирается кодом | в модели операции — необязательное поле условия `{ if: { clbits: number[], value: number } }` и операция `measure` с номером классического бита | классические провода и условные гейты в `board`; движок с ветвлением по исходам (в демо есть в `dm.js` для измерений) |
| Синхронизация кода со схемой | работает для кода без циклов и функций; при цикле схема показывается для чтения, развёрнутой | перевод «код → схема» всегда возможен; «схема → код» — только для плоских схем | свёртка повторяющихся блоков в циклы — исследовательская задача, в запуск не входит |
| Шум в песочнице | выключен | `options.noise` в `run`; предел по `limits.supportsNoise` | перенос `dm.js` за интерфейс движка |
| Аналитическая запись состояния | формула по амплитудам с округлением | функция `describeState(state): string` в `quantum-core` | распознавание известных состояний: Белла, GHZ, W, Дике |
| Запуск на реальном устройстве | нет | движок с `id` внешнего провайдера за тем же интерфейсом | отдельный проект |

Заглушки включаются и выключаются флагами конфигурации, без выкладки нового кода.

## 7.6. Согласованность браузера и сервера

В системе три места, где считаются одни и те же вещи: браузерный движок, интерпретатор Qiskit-lite и серверный
судья на настоящем Qiskit. Расхождение между ними участник воспринимает как ошибку платформы: «у меня глубина
6, а сервер пишет 7».

Требования:

1. **Общий набор сверки.** В репозитории лежит набор схем в переносимом виде с ожидаемыми значениями: число
   гейтов, двухкубитных гейтов, глубина, вектор состояния. Источник — эталоны банка
   ([`bank/core`](../../bank/core)) на сетках параметров плюс схемы на краевые случаи (пустая схема, гейты на
   непересекающихся кубитах, многоконтрольные гейты, измерения). Набор прогоняется в CI на обеих реализациях.
2. **Одно определение ресурсов.** Глубина — число слоёв при самой ранней расстановке, барьеры не считаются;
   число гейтов — без измерений и барьеров; двухкубитные — гейты на двух и более кубитах, кроме оракула.
   Определения записаны в [`bank/tools/sakit.py`](../../bank/tools/sakit.py) (`metrics`) и
   [`docs/ARCHITECTURE.md`](../ARCHITECTURE.md); браузерная реализация приводится к серверной.
3. **Имена гейтов.** Таблица соответствия «имя в интерфейсе ↔ имя в Qiskit ↔ имя в базисе задачи» — одна, в
   `quantum-core`, из неё же генерируется справка.
4. **Известные различия Qiskit-lite и Qiskit** перечислены на странице справки и проверяются: код, принятый
   интерпретатором, но отвергнутый сервером с `CE`, — случай для разбора. Счётчик таких случаев — метрика
   качества интерпретатора.
5. **Порядок кубитов** везде один: кубит $i$ — бит $i$ числа, как в Qiskit.

## 7.7. Требования к странице песочницы

- Состояния макета S1–S4: пустая схема, выбран гейт, режим «по шагам», после измерения.
- Ограничение 8 кубитов показывается до того, как участник в него упрётся.
- «Поделиться»: короткая ссылка создаётся на сервере; открытие чужой ссылки создаёт копию, чужая схема не
  изменяется.
- «Открыть как решение задачи»: из песочницы схему можно перенести в редактор задачи с тем же числом кубитов.
- Код схемы показывается на Qiskit, как в демо.
- Песочница доступна гостю целиком; серверные возможности (короткие ссылки сверх предела, запуск настоящего
  Qiskit) — участнику.

## 7.8. Приёмка

1. Тесты демо перенесены и проходят на пакетах `quantum-core` и `qiskit-lite`.
2. Набор сверки (7.6) проходит в CI в браузерной и серверной реализациях.
3. Замена движка проверена на макете: второй движок-пустышка за тем же интерфейсом подключается флагом, и
   редактор работает.
4. Отклик измерен на эталонных схемах банка для 8 и 12 кубитов и укладывается в 7.4.
5. Все ссылки песочницы из демо открываются на платформе.
