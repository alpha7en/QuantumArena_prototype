# 1. Продукт: роли, сценарии, страницы

[← к оглавлению](README.md)

## 1.1. Роли

| Роль | Кто это | Что может |
|---|---|---|
| Гость | посетитель без аккаунта | читать условия, работать в песочнице, решать открытые примеры локально; отправлять на проверку не может |
| Участник | зарегистрированный пользователь | отправлять решения, участвовать в раундах, иметь рейтинг и профиль |
| Автор задач | член команды или приглашённый составитель | видеть черновики своих задач, загружать версии, смотреть статистику решений |
| Жюри раунда | назначается на раунд | видеть все отправки раунда, отвечать на вопросы, объявлять, запускать перепроверку |
| Администратор | команда платформы | всё перечисленное, управление пользователями, раундами, банком |
| Представитель вуза | преподаватель; роль этапа «экзамены» | группы студентов, закрытые контрольные — в первой версии только место в модели данных |

Права проверяются на сервере по каждому запросу. Интерфейс лишь скрывает недоступное.

## 1.2. Главные сценарии

Опрос участников хакатона «Хакни квант» показал: до первой сданной задачи доходит примерно каждый пятый
(21,6 % и 24,2 % по двум трекам), а возвращаются ради регулярного потока задач и рейтинга. Отсюда порядок
сценариев по важности.

1. **Первая сданная задача.** Гость попадает на главную, открывает задачу первого уровня, собирает схему в
   редакторе, видит состояние и вероятности, нажимает «Отправить». Регистрация запрашивается в этот момент, а
   собранная схема не теряется. Цель: от входа на сайт до первого «принято» — меньше 10 минут.
2. **Регулярное решение.** Участник заходит в банк, фильтрует по теме и уровню, решает, читает разбор. Видит
   серию дней и прогресс по дереву тем.
3. **Раунд.** Участник записывается заранее, получает напоминание, в назначенное время открывает задачи,
   отправляет решения, следит за таблицей, после конца видит изменение рейтинга и разбор.
4. **Песочница.** Любой посетитель собирает схему, смотрит её по шагам, делится ссылкой.
5. **Подготовка задачи.** Автор оформляет пакет, загружает версию, видит результат прогонки эталона и неверных
   решений, отправляет на ревью второму эксперту.
6. **Проведение раунда.** Жюри собирает раунд из версий задач, проверяет его на тестовом запуске, в день
   раунда следит за очередью проверки и отвечает на вопросы.

## 1.3. Карта сайта

У каждой страницы — настоящий адрес. Переход по ссылке, обновление страницы, кнопка «назад» и открытие в новой
вкладке работают везде. Сейчас демо использует адреса на хэше ([`assets/js/app.js`](../../assets/js/app.js),
строки 22–39) — они заменяются.

Столбец «Отдача»: **С** — страница собирается на сервере и приходит готовой (быстрое первое отображение,
индексация поисковиками); **К** — приложение в браузере (редактор, живые данные).

## 1.4. Требования к страницам

Общее для всех страниц: шапка и подвал из макета; тёмная и светлая темы; состояния «загрузка», «пусто»,
«ошибка», «нет доступа» — у каждого блока с данными; заголовок вкладки и описание для поисковиков; работа с
клавиатуры.

### Главная `/`

- Блок ближайшего раунда с обратным отсчётом по серверному времени и кнопкой записи.
- Блок «начните с этой задачи» для гостя и «продолжить» для участника (последняя нерешённая задача).
- Лидеры рейтинга, подиум с анимацией из макета.
- Счётчики (задач, участников, отправок) — настоящие, из базы. Смоделированных чисел быть не должно:
  в демо они были помечены, на платформе их нет вовсе.

### Банк задач `/tasks`

- Список с колонками: номер, название, тема, уровень, доля решивших, статус для текущего участника
  (не открывал, пробовал, решено).
- Фильтры строятся из полей карточки ([`bank/CLASSIFICATION.md`](../../bank/CLASSIFICATION.md)): уровень, ствол и
  ветвь дерева, тип ответа («схема», «генератор», «динамическая», «программа»), «решается без кода» (`gui`),
  статус. Набор фильтров хранится в адресе, чтобы ссылкой можно было поделиться.
- Поиск по названию и номеру. Сортировка по номеру, уровню, доле решивших.
- Постраничная выдача с сервера; список не грузится целиком.
- Внутренние поля (`method`, `source.note`, `pitfalls`, эталон) участнику не отдаются никогда.

### Задача `/tasks/{id}-{slug}`

Самая важная страница. Макеты F1·4–8 описывают её состояния: пусто, принято, неверный ответ, лимиты, связность,
ошибка кода.

- **Левая панель:** условие (Markdown с формулами LaTeX), строки «вход» и «цель», ограничения в виде
  позитивного контракта, подсказки по одной, вкладки «отправки» и «разбор».
- **Редактор.** Вид зависит от фасета `answer` задачи:
  - `fixed` — доска схем и код, синхронные, как в демо;
  - `generator`, `hybrid` — только код; над кодом — предпросмотр схемы для выбранного значения параметра;
  - `dynamic` — доска с классическими проводами и условными гейтами. В демо таких гейтов нет: до появления
    поддержки на доске задача решается кодом, а доска показывает схему только для чтения **[Д]**;
  - `value` — поле ответа.
- **Нижняя панель:** вектор состояния, вероятности, счётчики ресурсов против лимитов задачи (гейты, глубина,
  двухкубитные гейты) — считаются в браузере при каждом изменении.
- **Кнопки.** «Проверить примеры» — локальная проверка открытых примеров в браузере, без вердикта.
  «Отправить» — отправка на сервер; пока идёт проверка, показывается положение в очереди и состояние.
- **Черновик** сохраняется на сервере (для участника) и локально (для гостя) без нажатия кнопок; у задачи
  один черновик схемы и один черновик кода.
- **Вердикт** приходит без перезагрузки страницы. Текст вердикта — короткий и предметный, как в демо:
  «превышен бюджет гейтов: 14 из 12», «вспомогательные кубиты остались не в $\lvert0\rangle$».
  Номер проваленного теста показывается, содержимое закрытых тестов — нет.
- **После «принято»:** открывается разбор, показываются ресурсы решения в сравнении с эталоном
  («ваша глубина 4, у эталона 4»), для задач с оценкой — баллы.

### Отправка `/submissions/{id}`

Код или схема (доска только для чтения), вердикт, результаты по группам тестов без содержимого, ресурсы, время
в очереди и время проверки. Чужие отправки по задачам банка закрыты; после окончания раунда отправки раунда
открываются всем — если жюри не решило иначе **[Д]**.

### Раунды

См. раздел [8](08_contests_rating.md). Страница раунда `/contests/{n}` одна, а её содержимое зависит от
состояния раунда: до старта — описание и регистрация; во время — задачи, таймер, моя строка таблицы; после —
итоги, изменение рейтинга, разборы.

### Рейтинг, профиль, настройки

- Рейтинг: таблица с поиском и фильтром по вузу, постраничная; титулы и цвета — по формуле демо
  ([`docs/DEMO_DATA.md`](../DEMO_DATA.md)).
- Профиль: график рейтинга, решённые задачи по дереву тем, серия дней, календарь активности, раунды.
- Настройки: имя, вуз, аватар; пароль и привязанные входы; параметры редактора; уведомления; выгрузка своих
  данных и удаление аккаунта (требование закона, раздел 9).

### Песочница

См. раздел [7](07_sandbox_simulator_stub.md). Отличие от демо: короткая ссылка хранится на сервере, длинная
ссылка со схемой внутри адреса остаётся рабочей.

### Обучение

Справочные страницы из демо ([`assets/js/pages/learn.js`](../../assets/js/pages/learn.js)) плюс трек «с нуля»:
цепочка задач первого уровня по ветвям дерева, по одному новому элементу на шаг. Содержимое трека — данные
(список задач и короткие тексты), а не код.

## 1.5. Общие требования к интерфейсу

| Требование | Мера |
|---|---|
| Ширины экрана | 1440, 1280, 1024, 768, 400 пикселей; поля — как в [`docs/DESIGN.md`](../DESIGN.md) |
| Мобильная версия | чтение условий, банк, рейтинг, профиль, таблица раунда — полностью; редактор — в упрощённом виде: код и просмотр схемы с прокруткой, перетаскивание гейтов не обязательно |
| Доступность | контраст не ниже 4,5 : 1; видимый фокус; все действия доступны с клавиатуры, включая доску схем; подписи для средств чтения с экрана |
| Скорость | первое содержательное отображение страниц «С» — до 1,5 с на канале 10 Мбит/с; отклик редактора на изменение схемы до 8 кубитов — до 50 мс |
| Языки | русский; все строки интерфейса в словарях, условия задач хранятся с кодом языка |
| Формулы | LaTeX, отрисовка на сервере там, где страница собирается на сервере |
| Время | везде показывается в часовом поясе участника с подписью пояса; расчёты — по серверному времени |
| Ошибки | сообщение говорит, что случилось и что делать; технические подробности — в журнале, не на экране |
