# 2. Перенос дизайна

[← к оглавлению](README.md)

Дизайн демо — главный актив, который нельзя потерять при переезде. Требование простое: **страница платформы
выглядит и движется так же, как соответствующий экран демо, и при этом удобнее в работе.** Всё, что
перечислено в этом разделе как существующее, переносится обязательно.

## 2.1. Где брать дизайн

| Источник | Что в нём | Статус |
|---|---|---|
| Figma, файл «QuantumLeetCode», страница «arena · прототип» | экраны: главная, вход, банк, задача во всех состояниях, песочница, раунды, рейтинг, профиль, настройки | первоисточник макетов |
| Figma, тот же файл, секция «компоненты · arena» | кнопки, поля, вкладки, статусы, плитки гейтов, строки таблиц, подиум, всплывающие слои | первоисточник компонентов |
| Figma, коллекции переменных `qlc/dark` и `qlc/light` | цвета двух тем | первоисточник токенов |
| Figma, файл «SPARQ.2 framework», библиотека `sparq/bg`; страница «arena · web-фоны» | фоновые рисунки: сфера, кольца, интерференция, линейка | первоисточник фонов |
| [`assets/css/tokens.css`](../../assets/css/tokens.css) | те же токены в коде | рабочая копия; при расхождении с Figma — сверить с дизайнером |
| [`assets/css/`](../../assets/css): `base`, `components`, `pages`, `editor`, `motion`, `bg`, `fonts` | вся вёрстка демо, около 1100 строк | образец для переноса |
| [`docs/DESIGN.md`](../DESIGN.md) | таблица «компонент Figma → класс», «экран Figma → адрес», намеренные отличия, правила движения | обязательное чтение перед вёрсткой |
| Живое демо | поведение: наведение, нажатие, появление блоков, подиум, доска | эталон для сравнения «до и после» |

Доступ к Figma выдаёт владелец файла. Если макета для страницы нет (список в разделе 1.3), страница собирается
из компонентов и показывается дизайнеру до вёрстки.

## 2.2. Токены

Переносятся без изменения значений. В коде платформы токены живут в одном месте — пакете дизайн-системы — и
выражены переменными CSS с теми же именами.

| Группа | Токены | Источник |
|---|---|---|
| Фоны | `--bg-base`, `--bg-panel`, `--bg-raised`, `--bg-inset` | `tokens.css` |
| Линии | `--line-subtle`, `--line-strong` | `tokens.css` |
| Текст | `--text-primary`, `--text-secondary`, `--text-muted` | `tokens.css` |
| Акцент | `--accent`, `--accent-hover`, `--accent-pressed`, `--accent-text` | `tokens.css` |
| Статусы | `--ok`, `--warn` | `tokens.css` |
| Движение | `--d-fast` 120 мс, `--d-base` 200 мс, `--d-slow` 360 мс, `--ease-out`, `--ease-io` | [`motion.css`](../../assets/css/motion.css) |
| Радиусы | 10 (кнопки, поля), 9 (плитки гейтов), 16 (карточки), 24 (большие карточки) | `DESIGN.md` |
| Сетка | поля 64, 40, 32, 16 пикселей на ширинах 1440, 1280, 1024 и мобильной | `DESIGN.md` |

Шрифты: Unbounded (заголовки, крупные числа), Onest (текст), JetBrains Mono (код, подписи, числа). Файлы лежат
локально в [`assets/fonts/`](../../assets/fonts), внешних запросов за шрифтами нет — так должно остаться.
Текстовые стили `.t-display`, `.t-h1` … `.t-kicker` переносятся как есть.

Темы: тёмная по умолчанию, светлая, «как в системе». Выбор хранится в профиле участника и в браузере гостя.
Страница, собранная на сервере, приходит сразу в нужной теме — без вспышки другой темы при загрузке.

## 2.3. Компоненты

Каждый компонент демо становится компонентом библиотеки интерфейса платформы с теми же состояниями. Полная
таблица соответствия — в `DESIGN.md`; здесь — что обязано быть в библиотеке.

| Компонент | Состояния | Сейчас в коде |
|---|---|---|
| Кнопка: основная, вторичная, контурная, прозрачная | обычное, наведение, нажатие, выключена, загрузка | `.btn*` в [`components.css`](../../assets/css/components.css) |
| Поле ввода, выбор, флажок | обычное, наведение, фокус, заполнено, ошибка, выключено | `.field`, `.control`, `.checkbox` |
| Вкладки, сегменты, метки | — | `.tab`, `.segmented`, `.chip` |
| Статус отправки | принято, неверный ответ, лимит, ошибка, проверяется, в очереди, черновик | `.status`, `statusHtml()` в [`parts.js`](../../assets/js/ui/parts.js) |
| Плитка гейта | обычная, наведение, выбрана, перетаскивается, выключена, ошибка, место вставки | `.tile-btn`, плитки на доске |
| Диск фазы на проводе | вероятность, фаза, признак запутанности | `Board.renderDisks` в [`board.js`](../../assets/js/ui/board.js) |
| Строки: задача, раунд, задача раунда, лидер, строка рейтинга | обычная, наведение, «моя строка» | `.trow`, `.rrow`, `.rtask`, `.srow`, `.prow` |
| Подиум, плитка показателя, итог раунда, обратный отсчёт | — | `podiumHtml()`, `.card.stat`, `.res-grid`, `countdownBig/Inline()` |
| Всплывающие слои: уведомление, окно, меню, подсказка | появление, закрытие | [`overlay.js`](../../assets/js/ui/overlay.js) |
| Пустое состояние, заглушка загрузки | — | `.empty`, `.skeleton` |
| Аватар | инициалы, фото | `.avatar` |
| Значки, 60 штук | — | [`icons.js`](../../assets/js/ui/icons.js), контуры выгружены из Figma |
| Шапка, подвал, навигация | гость, участник, во время раунда | [`chrome.js`](../../assets/js/ui/chrome.js) |

Статус «в очереди» новый: в демо проверка мгновенная. Его вид согласуется с дизайнером на основе «проверяется».

К библиотеке прилагается витрина компонентов (страница со всеми компонентами во всех состояниях в обеих
темах) — по ней принимается перенос.

## 2.4. Движение

Правила из `DESIGN.md` обязательны, их нарушение — дефект приёмки.

1. Движение объясняет событие: появилось, нажато, выбрано. Быстро и без отскока. Меняются только
   прозрачность и положение.
2. Анимация не мешает действию: всё на экране кликабельно с первого кадра, переход на другую страницу не ждёт
   конца анимации.
3. Соседние элементы появляются по очереди: ступень 80 мс, не больше пяти ступеней, сверху вниз и слева
   направо.
4. Блоки ниже первого экрана «спят», пока до них не долистали; при быстрой прокрутке пропущенное показывается
   сразу.
5. Анимация идёт один раз на открытие страницы. Липкие и фиксированные блоки не анимируются.
6. При системной настройке «уменьшить движение» остаются только смены цвета.
7. Страницы-редакторы (задача, песочница) не оживляются.

Что есть в демо и должно быть на платформе ([`motion.css`](../../assets/css/motion.css),
[`motion.js`](../../assets/js/ui/motion.js)): вход страницы со сдвигом на 8 пикселей; поочерёдное появление
заголовка, текста и кнопок на главной, схема въезжает справа; проявление блоков при прокрутке; счёт крупных
чисел от нуля; сжатие кнопок на 3 % при нажатии и подъём карточек-ссылок на 2 пикселя; появление всплывающих
слоёв с лёгким масштабом; подиум — блоки поднимаются в порядке 2, 1, 3, затем подписи и красная нить; плавная
смена темы за 300 мс.

Особенность многостраничного сайта: переход между страницами не должен давать пустой экран. Рекомендуется
сохранять шапку на месте и менять только содержимое, а анимацию входа страницы запускать после прихода данных.

## 2.5. Фоны, рубрики, логотип

- Фон не лежит на всей странице: рисунки стоят локально — сфера на главной и на входе, линейка у подвала,
  четверть колец на странице задач, интерференция на рейтинге. Красного градиента на страницу нет.
- Центр концентрического рисунка прячется за край или гасится маской; за подиумом и схемой рисунков нет.
- Маски фонов генерируются скриптом [`scripts/gen-bg.mjs`](../../scripts/gen-bg.mjs); скрипт переносится в
  сборку.
- Рубрика: моноширинная подпись прописными с красной чертой 14 на 1 пиксель. Логотип: слово `sparq` и метка
  `arena` с нарисованными чертой и скобкой.
- Знаки кет-векторов остаются только в формулах и названиях состояний; в интерфейсе их нет.

## 2.6. Что добавить ради удобства

Дизайн демо рассчитан на показ. Для ежедневной работы нужно доделать то, что в `DESIGN.md` и
[`docs/ROADMAP.md`](../ROADMAP.md) названо недоделанным.

| Что | Почему | Требование |
|---|---|---|
| Мобильная версия | в Figma не нарисована, в демо — только адаптивные правила | отдельные макеты для 400 пикселей: главная, банк, задача (чтение и код), раунд, таблица, профиль |
| Управление доской с клавиатуры | в демо гейты на доске выбираются только указателем | перемещение по клеткам стрелками, постановка гейта клавишей, удаление, отмена и повтор |
| Состояния данных | в демо данные всегда есть и приходят мгновенно | для каждого блока: загрузка (заглушка), пусто, ошибка с кнопкой «повторить», нет доступа |
| Длинные списки | банк вырастет до сотен задач, рейтинг — до десятков тысяч строк | постраничная выдача, поиск, «моя строка» закреплена |
| Проверка в очереди | вердикт приходит не мгновенно | состояние «в очереди, вы 14-й», затем «проверяется», затем вердикт; страницу можно закрыть |
| Потеря связи | редактор должен переживать обрыв | черновик хранится локально и досылается; отправка при обрыве не дублируется |
| Таблица раунда | тысячи строк, обновление вживую | своя строка закреплена, изменения подсвечиваются сменой цвета, без прыжков вёрстки |
| Разборы и подсказки | в демо показываются сразу | подсказки открываются по одной; разбор — после решения |
| Уведомления | в демо только колокольчик | колокольчик, почта, напоминание о раунде |

## 2.7. Приёмка дизайна

1. **Витрина компонентов** совпадает с секцией «компоненты · arena» по размерам, цветам, радиусам и состояниям
   в обеих темах.
2. **Экраны.** Для каждого экрана из таблицы «Экраны» в `DESIGN.md` снимок страницы платформы на ширине 1440
   сравнивается с макетом и с демо; расхождения либо исправляются, либо вносятся в список намеренных отличий
   с причиной.
3. **Движение.** Проверочный список из 2.4 проходится вручную на главной, рейтинге и странице раунда; отдельно —
   при включённой настройке «уменьшить движение».
4. **Темы.** Каждая страница просматривается в тёмной и светлой темах; контраст текста проверяется
   автоматически.
5. **Ширины.** Каждая страница просматривается на пяти ширинах из раздела 1.5; горизонтальной прокрутки
   страницы нет нигде.
6. **Автоматика.** Снимки витрины и ключевых страниц сравниваются при каждой сборке, чтобы дизайн не «уплывал»
   со временем.
