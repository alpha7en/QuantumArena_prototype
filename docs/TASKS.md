# Задачи: методика и формат

Каталог задач — в [TASK_CATALOG.md](TASK_CATALOG.md) (генерируется из кода). Здесь — как задачи устроены и как добавить новую.

## Принципы

Методика взята из наработок команды sparq (материалы к заявке на акселератор, раздел «Банк задач и методика составления») и применена к прототипу.

- **Свои условия, чужие идеи.** Из открытых соревнований (QCoder, IBM Quantum Challenge, Xanadu QHack, Microsoft Quantum Katas, Classiq, НТО) берётся *механика*, условия пишутся заново. 56 разобранных чужих задач лежат в библиотеке проекта (`resources/parsed_tasks`) и служат образцами, на платформу они не переносятся.
- **Позитивный контракт.** В условии перечислено только то, что разрешено («гейты H, X, CX; не больше 4n гейтов»), а не список запретов. Нарушения сообщаются коротко: «4 гейта из 3».
- **Эталон до публикации.** У каждой задачи есть эталонное решение; оно проходит судью в `npm test`.
- **Нет перебора.** Лимиты подбираются так, чтобы случайный поиск по схемам не решал задачу.
- **Честный статус.** Условия и эталоны составлены при разработке этого прототипа. Ревью вторым экспертом («решить вслепую») и бета на участниках сообщества **ещё не проводились**.

## Пять осей описания

| Ось | Варианты |
|-----|----------|
| Входное состояние | фиксированное `|0…0⟩`; произвольное неизвестное; зависящее от параметров |
| Формат ответа | фиксированная схема (собирается в редакторе); генератор схемы по параметру (`solve(n)`, только код); схема с измерениями |
| Набор гейтов | свободный; ограниченный базис; нативный базис |
| Связность | все со всеми; цепочка; кольцо; произвольный граф |
| Способ проверки | состояние; преобразование; чистота анцилл; распределение измерений |

## Шесть архетипов

| Код | Архетип | Суть |
|-----|---------|------|
| T1 | Подготовка состояния | получить заданное состояние из `|0…0⟩` |
| T2 | Синтез преобразования | собрать оператор в рамках бюджета гейтов или глубины |
| T3 | Оракул с очисткой | вычислить функцию и вернуть анциллы в `|0⟩` |
| T4 | Ядро алгоритма | Гровер, Дойч — Йожа, Бернштейн — Вазирани, QFT, оценка фазы |
| T5 | Ограничения железа | базис, связность, шум |
| T6 | Измерения и коррекция | базисы измерения, телепортация, коды |

## Уровни

| Уровень | Состав | Пример в банке |
|---------|--------|----------------|
| лёгкая | один архетип, свободные гейты или малый базис | состояние Белла |
| средняя | архетип + одно ограничение | GHZ на цепочке, полусумматор |
| сложная | два архетипа или архетип + два ограничения, параметр n | GHZ на цепочке из n, чётный-но-не-ноль, код Шора |

## Формат задачи в коде

Файлы `assets/js/data/tasks/*.js` экспортируют массивы объектов:

```js
{
  id: 'bell',                       // латиница, дефисы
  title: 'Состояние Белла |Φ+⟩',
  topic: 'запутанность', level: 1,  // 1 лёгкая · 2 средняя · 3 сложная
  archetype: 'T1',
  statement: ['Абзац условия. `Код` выделяется обратными кавычками.'],
  io: { in: '|00⟩', out: '(|00⟩ + |11⟩) / √2' },   // строки «вход» и «цель» в левой панели
  qubits: 2,                         // число кубитов; null — только код (параметрическая задача)
  wires: ['a', 'b'],                 // необязательно: подписи проводов
  initBits: [0, 0, 0, 0, 1],         // необязательно: начальные |1⟩ на проводах (подпись и вход)
  inputLabel: 'ψ',                   // необязательно: на q0 произвольное состояние
  limits: { gates: 3, depth: 2, twoQubit: 6, oracleCalls: 1,
            basis: ['H', 'X', 'Z', 'CX'], coupling: { kind: 'line' } },   // или функция (n) => {...}
  params: { name: 'n', values: [2, 3, 5], default: 3 },                   // для параметрических задач
  oracleArity: 3,                    // кубиты оракула-«чёрного ящика»
  noise: { eps: 0.05, slack: 0.02 }, // шум как часть условия
  suite: (param) => stateSuite({ n: 2, target: ... }),   // набор случаев — см. JUDGE.md
  reference: 'from qiskit import QuantumCircuit\n...',   // эталон на Qiskit-lite
  coach: [{ title, text }],          // необязательно: пошаговая подсказка
  hint: '...', hint2: '...',         // две подсказки
  analysis: ['Разбор...'],
}
```

Имена гейтов в `basis` — те, что видит пользователь: `H X Y Z S S† T T† √X P RX RY RZ CX CY CZ CH CP CRX CRY CRZ CCX CCZ MCX CSWAP SWAP`. Управляемые варианты получаются добавлением управляющих кубитов, поэтому `CCX` — это `X` с двумя управлениями.

## Как добавить задачу

1. Выберите архетип и уровень, сформулируйте ограничения как позитивный контракт.
2. Опишите задачу в одном из файлов `assets/js/data/tasks/` и добавьте её `id` в `ORDER` в `assets/js/data/tasks.js`.
3. Напишите `suite` из конструкторов `builders.js`; ожидание задавайте *независимо от эталона* (формулой, таблицей, классической функцией), чтобы эталон проверялся, а не подгонялся.
4. Напишите эталон на Qiskit-lite.
5. `npm test` — эталон должен пройти, а пустая схема и эталон без последнего гейта не должны.
6. Если можно ошибиться «почти правильно» (фаза, мусор в анцилле, порядок), добавьте негативный тест в `tests/judge.test.mjs`.
7. `node scripts/gen_catalog.mjs` — обновить каталог.

## Правила гибридизации

Новые задачи собираются из элементов с известным способом проверки (архетип + ограничение, архетип + тип входа, архетип + архетип). Для гибрида должен существовать способ проверки из каскада судьи; если его нет, задачу не публикуют. Один новый элемент на уровень сложности. Примеры из банка: «GHZ на цепочке из n» (подготовка состояния + связность + бюджет глубины), «Чётный, но не ноль» (оракул + бюджет анцилл), «Равны ли регистры» (фазовый оракул + произвольный вход).
