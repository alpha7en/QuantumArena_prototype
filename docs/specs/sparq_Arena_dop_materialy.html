1. Банк задач и методика составления

Лекций и учебников по квантовым вычислениям достаточно, а практических задач с автоматической проверкой почти нет. Собственные задачи — главная ценность платформы. Составить такую задачу трудно: нужно, чтобы её можно было проверить автоматически, чтобы у неё было эталонное решение и чтобы её нельзя было решить перебором.

6 архетипов

T1. Подготовка состояния

Получить заданное состояние из |0…0⟩.

T2. Синтез преобразования

Собрать заданный оператор, уложившись в бюджет гейтов или глубины.

T3. Оракул с очисткой

Вычислить функцию и вернуть вспомогательные кубиты в исходное состояние.

T4. Ядро алгоритма

Гровер, Дойч–Йожа, Бернштейн–Вазирани, КПФ, оценка фазы.

T5. Ограничения железа

Нативный базис и неполная связность, маршрутизация.

T6. Измерения и коррекция

Схемы с промежуточными измерениями, телепортация, коды коррекции ошибок.

Как появляется новая задача

1. Идеяархетип и ограничения
2. Карточкапо шаблону: условие, формат ответа, ресурсы
3. Эталонавтор решает сам, фиксирует ресурсы
4. Тестыграничные случаи, проверка на перебор
5. Ревьювторой эксперт решает вслепую
6. Бетана участниках сообщества

Принцип «позитивного контракта»: в условии перечислено только то, что разрешено («гейты H, X, CX; не более 4n гейтов»), а не длинный список запретов. Нарушения система сообщает коротко: «превышен бюджет гейтов: 14 из 12».

2. Правила гибридизации задач

Гибридизация — способ быстро получать новые задачи с проверенной механикой. Новая задача собирается из элементов, у каждого из которых уже есть способ проверки: архетипа, ограничения, типа входа и формата ответа. Сложность растёт с числом соединённых элементов.

Типы гибридов

  • Архетип + архетип. Оракул внутри алгоритма; подготовка состояния, затем фазовая метка.
  • Архетип + ограничение. Знакомая задача на цепочке кубитов, в нативном базисе, с бюджетом глубины или вспомогательных кубитов.
  • Архетип + тип входа. Та же операция, но на произвольном неизвестном входе: проверяется уже преобразование, а не одно состояние.
  • Перенос сюжета. Механика из классической олимпиадной задачи или прикладной области переносится в квантовую постановку.

Правила

  1. Проверяемость. Для гибрида должен быть способ проверки из каскада тестирующей системы. Если его нет — задачу не публикуем.
  2. Эталон до публикации. Автор решает задачу сам и фиксирует ресурсы эталона.
  3. Нет перебора. При заданных ограничениях пространство схем должно быть слишком большим для перебора.
  4. Один новый элемент на уровень. Для учебных треков сложность растёт по одному элементу.
  5. Механика, а не текст. Из источников берём идею механики, условия пишем свои.
  6. Второй эксперт. Каждую задачу решает вслепую ещё один участник команды.

3. Примеры задач в формате платформы

Короткие примеры, показывающие формат карточки и гибридизацию. Полные условия, тесты и эталоны хранятся в банке задач.

SA-101. GHZ на цепочке
Уровень 2 · гибрид: подготовка состояния (T1) + связность (T5) + бюджет глубины

Даны n кубитов (2 ≤ n ≤ 12) в состоянии |0…0⟩, соединённые в цепочку q₀ – q₁ – … – qₙ₋₁. Двухкубитные гейты разрешены только между соседями. Получите состояние (|0…0⟩ + |1…1⟩)/√2.

Гейты: H, CXГлубина ≤ ⌈n/2⌉ + 1Ответ: solve(n) → QuantumCircuitПроверка: сравнение состояний

Идея: «наивное» решение — цепочка CX слева направо — даёт глубину n и не проходит. Нужно начать из середины цепочки и распространять запутанность в обе стороны.

SA-205. Чётный, но не ноль
Уровень 3 · гибрид: оракул (T3) + бюджет вспомогательных кубитов

Реализуйте оракул |x⟩|y⟩ → |x⟩|y ⊕ f(x)⟩ на n входных кубитах (2 ≤ n ≤ 6), где f(x) = 1, если в x чётное число единиц и x ≠ 0…0. Можно использовать не более одного вспомогательного кубита; после схемы он должен вернуться в |0⟩.

Гейты: X, CX, многоконтрольный X≤ 1 вспомогательный кубитВход: произвольныйПроверка: преобразование + чистота вспомогательных кубитов

Идея: две простые части — чётность и проверка на ноль — нужно совместить, не оставив «мусора» во вспомогательном кубите. Ошибка с неочищенным кубитом ломает интерференцию в алгоритмах, где такой оракул используется.

SA-310. Равны ли регистры
Уровень 4 · гибрид: фазовый оракул (T3) + произвольный вход + оптимизация

Даны два регистра a и b по n кубитов (1 ≤ n ≤ 4). Реализуйте преобразование |a⟩|b⟩ → (−1)^[a = b] |a⟩|b⟩. Баллы зависят от числа двухкубитных гейтов.

Гейты: H, X, CX, CZ, CCXВспомогательные кубиты — только чистыеОценка: число двухкубитных гейтов

Идея: задача для отбора — проверяет знание приёма «вычислить, применить фазу, развычислить» и умение экономить ресурсы.

4. Тестирующая система: концепция

В обычном программировании проверка проста: запустить код и сравнить вывод с ответом. В квантовом программировании так не работает. Тестирующую систему разрабатывает научная часть команды как отдельную академическую задачу.

Почему простая проверка ошибается

Результат вероятностный

Схема выдаёт распределение, а не одно число. Два верных решения могут отличаться ненаблюдаемой глобальной фазой — система обязана считать их одинаковыми.

Вспомогательные кубиты

У участника и у эталона их может быть разное число. Если вспомогательный кубит не очищен, решение выглядит почти верным, но ломает алгоритм, в который его встроят. Простое сравнение выносит здесь ложный вердикт в обе стороны.

Размер растёт экспоненциально

Каждый кубит удваивает размер описания состояния. Полная проверка преобразования быстро становится неподъёмной по памяти.

Каскад проверок (теоретическая модель)

1. Быстрые проверкиразрешённые гейты, бюджет, глубина, связность
2. Точная проверкадля классов схем, которые проверяются эффективно
3. Проверка с учётом вспомогательных кубитовэквивалентность на допустимом подпространстве
4. Выборочное тестированиедля сложных случаев, с оценкой надёжности

Решение проходит каскад от дешёвых проверок к дорогим. Большая часть ошибок отсекается на первых шагах, дорогие методы нужны только там, где без них нельзя.

Статус

  • Задача проверки формализована: что значит «решение верно» при разном числе вспомогательных кубитов.
  • Разобраны случаи, где простая проверка ошибается, и предложена каскадная схема.
  • Изучены существующие инструменты проверки эквивалентности квантовых схем и их ограничения.
  • Готовится научная статья. Следующий шаг — программная реализация ядра.

Математические детали и алгоритмы не раскрываются: заявочные материалы по Правилам не должны содержать ноу-хау.
