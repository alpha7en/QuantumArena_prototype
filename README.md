# QuantumArena (Квантовый LeetCode)

Архив наработок по платформе олимпиадного программирования квантовых алгоритмов (**QuantumArena / Quantum LeetCode**).

---

## 1. Сайт-прототип
Разработан интерактивный веб-прототип платформы. Прототип демонстрирует общую архитектуру сайта, UX решения задач, визуальную песочницу и конвертацию схемы в Qiskit (пока без серверного бэкенда проверки).

* 🌐 **Онлайн-демо:** [https://alpha7en.github.io/QuantumArena_prototype/](https://alpha7en.github.io/QuantumArena_prototype/) *(или локально [`index.html`](index.html))*

## 2. Архитектура сайта и симулятор
* **Общая платформа:** главный экран с текущими контестами, архив мероприятий, профиль с ELO-рейтингом, split-view рабочая область.
* **Песочница:** визуальный редактор квантовых схем с реактивным пересчетом вектора состояния на лету (без кнопки Run), удалением элементов (клик по корзине / drag-out), 3D сферой Блоха и символьным распознаванием состояний (CAS).
* **Связь кода и схемы:** двусторонняя синхронизация (Код $\leftrightarrow$ Графическая схема).

## 3. Банк и шаблонизация задач
Для создания соревнований выделены шаблоны и параметры задач:
* **Тип ответа:** функция `solve(n, ...) -> QuantumCircuit`.
* **Тип схемы:**
  * *Тип A (Фиксированная):* схема статична, можно собрать в визуальной песочнице;
  * *Тип B (Параметризованная):* схема строится кодом в зависимости от входных данных ($n$, битовые маски, функции).
* **Тип начального состояния:** фиксированное ($|0\dots0\rangle$), полностью произвольное ($|\psi\rangle$) или параметризованное.
* **Топология связности (Coupling Map):** полная (All-to-All), линейная цепочка ($q_0-q_1-q_2$), сетка чипа или произвольный граф; при отсутствии ребра $(q_i, q_j)$ участник обязан сам делать $SWAP$-маршрутизацию.
* 📁 **Банк задач:** папка [`tasks/`](tasks/) — 43 задачи с сайта QCoder и IBM Challenge с разборами и тестами в [`tasks/parsed/`](tasks/parsed/).

## 4. Проверяющая система (Auto-Judge) и Безопасность
* **Двухконтурная проверка:** клиентский WASM ($n \le 6$, моментальный отклик) + серверный Docker/gVisor ($n > 6$, скрытые тесты).
* **Валидация ограничений:** проверка бюджета гейтов, глубины цепи и графа связности кубитов (`CouplingMapValidator`).
* **3 Уровня защиты:**
  1. *L1 (Хост):* песочница gVisor, изоляция сети (`--net none`), AST-whitelist;
  2. *L2 (Qiskit API):* запрет интроспекции фреймов и подмены валидатора;
  3. *L3 (Anti-Auto-Synthesis):* детекция автоматического синтеза схем через `qiskit.synthesis` (анализ иррациональных углов, KAK-сигнатур, AST-бан пакетов).
* 📄 **Спецификация:** [`docs/judge_and_security.md`](docs/judge_and_security.md)

## 5. «Серая зона» и открытые R&D вопросы
* **Динамические цепи:** задачи с измерениями (`measure`) и условными гейтами (`c_if`, QEC) требуют симуляции на шотах (`AerSimulator`) вместо матричного `Statevector`.
* **Символьный CAS:** алгоритмы надежного обратного сворачивания численных амплитуд в аналитические базисы.
* 📄 **Список вопросов:** [`docs/open_questions.md`](docs/open_questions.md)
